# 第十七册 症状驱动检索与治疗建议流程

本册把前面各分册的辨证知识，落成一个"说症状直接出判断和治疗建议"的成型流程。它的目标很明确：用户只要描述身体不舒服，系统就按五格坐标把症状变成可追溯的辨证结论，并给出能自己做的调理与需要医生做的检查。流程分两层检索，一层是本技能深读过的分册，一层是 848 本中医古籍数据库。两层都遵守公有领域引用、白话原创、方剂只列药味、安全闸门不变。

## 一、两层检索架构

第一层，本地深读分册（references/00 至 19）。这是辨证的主脑，全部可现场推理、结论可追溯。症状进来先在这里匹配候选证型、取原文依据、定治法方向。

第二层，848 本中医古籍数据库（tcm-corpus/tcm）。这是按需拉取原文、核对版本、关联方证的总盘。平时不逐本读，问到具体书或具体条文时去库里查原文逐字核对，再写进输出。

两层的关系是：第一层给结论与依据，第二层做原文核实与扩证。没有第二层也能工作，有了第二层结论更稳、出处更广。

## 二、848 本语料连接器规范

### 数据来源

GitHub 仓库 jobkoko/tcm-database，子目录 tcm/ 下 848 本古籍，UTF-8 编码的 .txt 文件，另有 古籍目录.csv 全库书目。数据整合自殆知阁古籍语料库、中华医典等开源项目，经编码统一、去重、作者修正而成，属公有领域古籍的整理本，可合法检索与引用原文短句。

### 默认存放路径

技能包之外的数据目录：`D:/WB/2026-11-12-16-11-17/tcm-corpus/tcm`。脚本 `scripts/retrieve.py` 用环境变量 TCM_CORPUS 或命令行参数可改路径。语料刻意放在技能包之外，保证技能包轻量、可分发，原始语料随取随用。

### 语料就位状态

语料已由维护者下载完成，848 本全部落在默认路径，使用者不需要执行任何下载命令。沙箱内仓库克隆与压缩包通道不可达，实际改用原始文件分发节点逐文件拉取，配合并发、重试与断点续传补齐，并对中文路径做百分号编码。语料就位后已由 `scripts/build_index.py` 建立倒排索引，`scripts/retrieve.py` 自动启用原文检索。

语料目录万一缺失，脚本只给中文提示，不会把下载操作交给使用者，也不会静默失效；此时仍可用二十册深读分册正常出判断。

### 分类法（15 类，文件前缀）

医经基础 Y、本草方药 B、伤寒 S、金匮 J、方剂 F、针灸经络 Z、温病内科 N、五官科 K、外科伤科 W、妇科 G、儿科 E、推拿养生 T、医案医话 A、诊法 D、综合 O。文件名格式为「分类代码-序号-书名.txt」，书内嵌元信息头（书名、作者、朝代、年份）。

### 查询协议

1. 先用症状关键词在 848 本语料里全文检索，命中即返回书名、作者、朝代、片段。
2. 取到的原文短句可引（公有领域），库方的点校说明、整理成果属其权利，不整段搬运。
3. 引文须回五格坐标落位，并在输出标注来自哪一本书的哪一段。
4. 库内查不到的，回到第一层分册或按需联网核实，禁止凭记忆编造篇名与条文。

### 版权边界

语料为古籍公有领域文本的整理，引用短句合规；现代点校、注释、白话译本、商业数据库内容不复制。涉及犀角、虎骨等受保护动物药材的条文，只作历史记载，不转化为现代使用建议。

## 三、症状到判断的成型 SOP

拿到症状描述，按下面五步走，跳过任何一步都可能翻车：

第一步，跑红旗清单。只要命中一条（如高热神昏、胸痛喘促、剧烈头痛呕吐、大出血、孕产急症、小儿惊风等），立刻停止辨证，直接建议就医或急诊，说清为什么。

第二步，填五格坐标。把症状逐项归位：位置（表里、六经、卫气营血、三焦、脏腑）、性质（寒、热、寒热错杂）、力量（虚、实、虚实夹杂）、物质（气、血、津、阴、阳哪块出问题）、病因（六淫、痰瘀、七情、饮食）。空格子用最少提问补齐。

第三步，匹配候选证型。用 `scripts/retrieve.py` 跑症状关键词，脚本会从内置症状词典与二十册分册里给出候选证型、五格坐标、依据分册、能自己做的事，并标置信度。高置信度要主症齐备无反证；中低置信度只给方向，写明还缺哪几项。

第四步，取典籍依据与扩证。候选证型回到对应分册核对提纲证与方证；若需要某部未深读书的原文，去 848 本语料里查，或按 references/15 的按需核实协议联网补入。每条依据格式固定：书名加篇名或条文号，原文短句，白话解释，用在哪一步。

第五步，定治法出建议。先说调理方向（辛温解表、清热生津、温中散寒、疏肝健脾之类），再谈代表方只作知识说明。能自己做的落在饮食起居观察；涉及内服方剂、剂量、针刺、有毒药材，一律写清须执业中医师面诊后开方。

## 四、运行检索脚本

症状进来先跑一次脚本取草稿，再由人工或本技能精炼成最终输出：

```bash
python "D:/WB/2026-11-12-16-11-17/zhongyi-classics/scripts/retrieve.py" "怕冷重 发热轻 无汗 头身痛 脉浮紧"
```

脚本会做五件事：检查红旗、匹配候选证型与五格坐标、检索二十册分册里的相关段落、用倒排索引检索 848 本原文、对代表方做图谱交叉验证并输出中文组成与归经。输出按固定模板，可直接作为辨证草稿。

可选参数：`--corpus 路径` 指定语料目录；`--json` 输出结构化结果便于程序调用；`--top N` 控制返回条数。

## 五、固定输出模板

```text
【一句话结论】用大白话说身体大概处于什么状态
【怎么判断出来的】把症状逐条对应到五格坐标，列出支持点与反证
【典籍依据】书名·篇名／条文号 + 原文短句 + 白话 + 用在哪
【治法方向】先治什么、后顾什么
【能自己做的事】饮食、起居、观察记录，写清楚怎么做、做多久
【需要医生做的】复诊指征、需要面诊核对的项目
【还要补充的信息】缺哪几项，补齐后能更准
【安全提醒】固定免责语 + 本次命中的具体风险
```

## 六、安全闸门（每次输出前必过）

免责声明、红旗排除、特殊人群（孕产、老弱、小儿、过敏体质）、药材风险、剂量口径、法规禁用药材、引用可追溯、置信度标注。任何一项没过就改到过为止，绝不在信息不足时给高置信度结论。
