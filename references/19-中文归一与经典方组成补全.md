# 中文归一与经典方组成补全

本册记录 v0.13.0 解决的两个硬问题。

第一，完整中医知识图谱的原始结构为英文与无调拼音，药名、方名、性味、归经、主治都是英文，直接输出会出现英文药名与英文归经。

第二，图谱中相当一部分经典方的组成字段本身为空，六味地黄丸、桂枝汤都在其中，交叉验证时会出现空组成。

本版立下两条硬约束，并在代码里做闸门校验。

1. 面向用户的所有内容必须是中文，不出现拉丁字母。归一失败写中文「待核」，绝不透出英文原名或拼音原名。
2. 已核实经典方名录内每一首方都必须有真实的中文药味组成，不能以空列表、英文或纯占位符代替。

代码标识符、文件名、脚本参数属于工程约定，不在这条约束内。

## 一、中文归一字典与运行模块

### 数据来源

图谱随包提供官方名称对照文件 `4Nov2024_connector.json.gz`，其 `word_maps` 收录 BATMAN 与 American Dragon 两套中英名称映射。构建脚本 `build_zh_dict.py` 从中反查中文名，得到静态字典 `scripts/zh_dict.json`。

反查时处理三个坑。

- 官方键末尾带波浪号加数字的消歧后缀，例如桂枝汤对应的键末尾带数字 20，必须剥离后缀才能与图谱键对齐。
- 剥离后缀后会产生噪声映射，例如六味地黄丸对应的键被错配成浓缩丸。用拼音工具把中文候选转回无调拼音，必须与规范键严格一致才收录。
- 部分常用药与术语官方对照未收，另以人工核实表补齐，含炮制前后缀、性味、四气、归经、功效术语。

字典最终包含药名归一 2203 条、方名归一 28377 条，另含药名前缀、后缀、性味、四气、归经、功效六组映射。

### 运行模块

`scripts/zh_normalize.py` 在运行时只读静态字典，不读 parquet、不读对照文件、不联网。主要函数如下。

| 函数 | 作用 |
| --- | --- |
| `key` | 规范键，大写、去空格标点、剥离消歧后缀 |
| `herb_zh` | 药名拼音或英文转中文，含炮制前后缀拆解 |
| `formula_zh` | 方名拼音或英文转中文 |
| `meridian_zh` | 归经英文转中文 |
| `taste_zh` / `temp_zh` | 性味与四气英文转中文 |
| `action_zh` | 英文功效与主治转成已登录的中文要点，未登录词不透出 |
| `safe_zh` | 输出前最后一道闸，保证返回纯中文字符串 |
| `to_zh_list` | 批量归一、去重、保序 |

`safe_zh` 有一条容易踩空的判定。纯中文名经 `key` 处理后汉字会被滤掉，得到空串，因此必须先判「无拉丁字母且含汉字」直接放行，再判无效键，否则整库中文药名会被误判为待核。

覆盖验收数据：图谱组成字段与关系边涉及的 957 个药名中，948 个可直接归一，覆盖率 99.1%；`safe_zh` 输出含拉丁字母的条数为 0。少数无法归一者统一写「药名待核」。

## 二、经典方组成补全的三层来源

### 缺口统计

读取完整图谱并合并 `relations` 的 `contains` 关系边之后，2575 首方中仍有 987 首组成字段为空。其中 433 首是英文现代病名条目，554 首可归一为中文方名。人工核实库覆盖其中 194 首，古籍语料共识库再补 215 首，余下 145 首主要是现代成药、单味药、仅在医案中被提及的方名与图谱缺载条目。

主流程 `SYNDROME_FORMULA` 映射的全部代表方共 46 个，在人工核实库中已全覆盖。

### 三层来源与优先级

| 优先级 | 来源 | 文件 | 规模 | 说明 |
| --- | --- | --- | --- | --- |
| 一 | 经典方人工核实库 | `scripts/classic_formulas_zh.json` | 237 首 | 逐条据公有领域经典方剂记载补齐，含出处与证型，优先级最高 |
| 二 | 古籍语料共识库 | `scripts/corpus_formulas_zh.json` | 10265 首，其中高可信 4455 首 | 从 848 本古籍原文抽取，只用高可信条目 |
| 三 | 图谱自身组成与关系边 | 四个 parquet | 全量 | 已经中文归一，作为兜底 |

人工库最后写入，覆盖前两层，保证经典方以已核实组成为准。

### 语料抽取的质量控制

早期版本扫描全部 848 本书并取「药味最多者」，结果被医案、本草注文与同名加减方污染，六味地黄丸混入蔓荆子与川芎，桂枝汤混入赤石脂与附子。本版改为以下规则。

- 22 本方剂专书按可信度排序优先，其余书目只接受汤、散、丸、饮、膏、丹、煎、锭、饼、酒、方一类经典方名。
- 只在篇名段落开头 24 行内取药味，剥离剂量括注与炮制注文，组成长度限 3 至 20 味。
- 古籍组成常被换行打断，故用药味密度窗口，允许 2 个非药味词间隔，取药味最密集的一段，不再取「第一段连续药名」。
- 熟地、生地、山茱肉、丹皮、白茯苓一类异名统一归到通行正名，让不同书目的同一组成可以合并计票。
- 同一方名收集全部候选，按「独立书目重复数加权加方剂专书加权」投票取共识，不再取药味最多者。没有跨书共识且不出自方剂专书的条目标为待核，只作兜底。

修好之后的抽样结果：桂枝汤为桂枝、白芍、生姜、甘草、大枣；六味地黄丸为熟地黄、山茱萸、山药、茯苓、牡丹皮；小柴胡汤为柴胡、黄芩、人参、甘草、半夏、生姜、大枣。人工库另补泽泻等典籍通行药味，最终以人工库为准。

### 人工核实库的补遗

图谱中仍无组成但确属经典方的中文方名，另补 69 首，例如麻杏苡甘汤、栝楼薤白白酒汤、葶苈大枣泻肺汤、大黄牡丹皮汤、厚朴生姜半夏甘草人参汤、建瓴汤、升陷汤、定经汤、缩泉丸、金铃子散、良附丸、四妙勇安汤、加减葳蕤汤、清宫汤、五汁饮、宣痹汤、托里消毒饮、消瘰丸、痛泄要方、芍药甘草汤、桂枝甘草汤等。

受保护药材按技能既有规则处理。犀角以水牛角代，羚羊角以山羊角代，乌头、朱砂、雄黄一类在证型中写明须医师核定，不提供剂量。

## 三、经典方名录边界与硬校验

系统只把名录内的方视为经典方。名录由人工核实库与语料共识库的高可信经典方条目构成，命名具备汤散丸饮膏丹煎一类特征，且不含片、胶囊、颗粒、口服液、冲剂、软膏、糖浆等现代剂型标记。

名录内每一首方都有中文药味组成，检索层硬校验。

名录外的条目，包括英文现代病名条目、现代成药、单味药、图谱缺载方名，统一标为「待核条目（非经典方）」，并输出一句中文说明，写明图谱与古籍语料均未检出可靠组成、须医师核定、不作为经典方使用。这样既不编造药味，也不会出现冒充经典方的空组成。

`verify_graph.py --audit` 可随时复核。当前结果：已核实方剂 5145 首，经典方 4045 首，空组成经典方 0 首，非中文药味 0 条。主流程 46 个代表方逐一出报告，全部有真实中文药味，结论文本无拉丁字母。

## 四、主流程输出

`scripts/retrieve.py` 的图谱交叉验证段落现包含以下内容，全部中文。

- 图谱来源，如「完整中医知识图谱（已中文归一）」或「离线种子图谱（公有领域精选子集）」。
- 代表方、对应证型、条目类型。
- 代表方组成，只列药味，不给剂量。
- 组成依据与方剂出处。
- 归经覆盖与药味性味归经。
- 交叉验证结论，级别为一致、提示、待核、信息。

检索片段的书名显示也做了中文处理。带编号与扩展名的文件名转成《书名》，证型依据里的分册编号转成「深读分册第几册」，古籍原文片段清除转义标记与拉丁字母。语料目录未就位时不再输出下载命令，改为中文说明，避免把工程操作交给使用者。

## 五、用法与验收

```bash
python scripts/verify_graph.py 六味地黄丸 --syndrome=肾阴虚
python scripts/verify_graph.py 桂枝汤 --syndrome=太阳表虚
python scripts/verify_graph.py --herbs=石膏,知母,甘草
python scripts/verify_graph.py --audit
python scripts/retrieve.py "高热 怕热 大汗 大渴 脉洪大"
python scripts/retrieve.py "腰膝酸软 盗汗 头晕耳鸣 口干" --json
```

验收要点：组成不为空且全为中文药味；组成依据可追溯；归经与性味为中文；结论无英文或拼音；剂量不出现；受保护药材已标替代或提示。结构化输出的字段名为工程约定，字段取值全部为中文，可直接核对。

## 六、安全与版权边界

- 组成只列药味，不给可自行抓药的剂量，剂量一律由执业中医师面诊核定。
- 查不到的依据写待核，不编造篇名、条文号、方剂组成、药物归经。
- 848 本古籍语料与经典方组成为公有领域事实性知识，白话解释与结构为原创整理。
- 完整图谱为 CC-BY-NC-4.0 非商业许可，衍生结论仅作教学与非商业研究，引用须注明来源。
- 红旗清单命中的急症立即停止辨证，建议就医或急诊。
