# 倒排索引检索与 DragonTCM 图谱交叉验证

本册说明技能在 v0.11.0 接入的两套工程能力：848 本古籍库的倒排索引（提速去重），以及 DragonTCM 图谱的药物归经与方证关联交叉验证。两者都服务于同一目标，即用户只说症状，系统就能较快给出可溯源、可校验的判断与治疗建议。

v0.13.0 对图谱部分做了全中文归一与经典方组成补全，本册中「英文结构」「拼音桥接」「空组成标待核」的描述为 v0.12.0 当时的状态，现行规则以 `references/19-中文归一与经典方组成补全.md` 为准。

## 一、848 本古籍库倒排索引（提速去重）

### 数据来源与落地
原始语料来自公开 GitHub 仓库 jobkoko/tcm-database，含 848 本中医古籍纯文本与《古籍目录.csv》，按 15 个门类归档。语料存放于技能包之外的 `D:/WB/2026-11-12-16-11-17/tcm-corpus/tcm`，保证技能包轻量、可分发的特性不受影响。

### 索引构建
脚本 `scripts/build_index.py` 扫描全部 txt，做三件事。
1. 解析每本书的头部元数据（书名、作者、朝代、年份）写入 `meta.json`。
2. 以中文二元字组（bigram）为索引项，建立倒排表 bigram 到文档编号的映射，压缩存为 `index.pkl.gz`。检索时先用查询词的二元组在倒排表中收窄候选文档，再只在这些文档里扫描原句，避免每次全库遍历。
3. 生成去重报告 `dup_report.json`，记录重复行组（同一段落在多书出现）与同名书组，供检索结果去重。

### 检索
脚本 `scripts/corpus_search.py` 提供 `search_corpus(query, top, use_index)`，优先用索引收窄候选，候选过多时退化全扫，结果按行内容去重后返回。检索词命中的原文片段会带书名、作者、朝代、文件名一并回传。

### 用法
先构建一次索引，之后随语料更新可重建。
```
python scripts/build_index.py
python scripts/retrieve.py "怕冷 无汗 身痛"
```
语料缺失时，脚本会提示把仓库的 `tcm/` 目录放到默认路径，或加 `--corpus 路径` 指定，不会静默失效。

## 二、DragonTCM 图谱交叉验证（药物归经与方证关联）

### 数据来源与许可
完整图谱为 HuggingFace 数据集 `f-galkin/DragonTCM`，包含 1119 个病证、2580 首方剂、1044 味药物、28735 条关系，衍生自美国 Dragon 网站与 Joel Penner 的工作。许可为 CC-BY-NC-4.0，仅限非商业使用，引用时须同时注明 Penner/McDonald 原著与 Galkin 数据集。

沙箱无法直连 huggingface.co，已通过镜像 `hf-mirror.com` 将四个 parquet 文件（herbs、formulas、conditions、relations）下载到 `D:/WB/2026-11-12-16-11-17/dragontcm/` 对应子目录。`scripts/verify_graph.py` 检测到该目录即优先自动加载完整图谱，否则回退种子子集。读取 parquet 依赖 `pyarrow`（已用阿里云镜像安装），无需 pandas。

### 图谱真实结构与中文桥接
完整图谱为英文结构，与种子的中文字段不同，加载时做三件事以让中文查询直接命中。
1. 药名与方名为无调拼音大写（如 `LIU WEI DI HUANG WAN`、`GAN CAO`），归经为英文（如 `Spleen`、`Stomach`）。脚本用 `pypinyin`（`Style.NORMAL`）把中文名转成无调拼音大写，并去掉空格归一为内部键，与图谱命名精确匹配。
2. `herbs` 的 `properties`、`formulas` 的 `composition` 字段是 JSON 字符串而非对象，加载时先解析再取归经、性味、组成。
3. 归经英文经 `EN2ZH_MERIDIAN` 映射归一为中文（`Spleen` 归脾、`Stomach` 归胃等），使方证一致性判断直接用中文经络名。

### 组成补全与方证关联
部分经典方（如六味地黄丸、桂枝汤、麻黄汤）在图谱中 `composition` 为空，但其组成可从 `relations` 的 `contains` 边（formula→herb，共 14608 条）补全；方剂主治的病证由 `treats` 边（condition→formula/herb）反向聚合补全。加载时按去空格大写去重合并，避免同一味药重复出现。v0.12.0 对图谱本身确无组成记录的方剂如实标注待核。v0.13.0 已改为按人工核实库、古籍语料共识库、图谱自身组成三层补齐，经典方名录内每首方都有中文药味组成，详见 `references/19`。

### 离线兜底种子
技能内附带 `scripts/dragontcm_seed.json`，为公有领域中医基础常识的精选子集（当前含 81 味药、38 首经典方，含归经、性味、组成、主治、治法）。该种子明确标注为不完全子集，用于在完整图谱缺位时仍能做基础交叉验证。完整图谱就位后自动覆盖种子。

### 交叉验证逻辑
脚本 `scripts/verify_graph.py` 对给定的方剂名、药物列表或证型做三类校验。
1. 组成解析：从图谱取方剂的组成药物（含 relations 补全）。
2. 归经一致性：汇总组成药物的归经，检查是否覆盖该证型所指向的经络（如脾虚指向脾经）。覆盖则标一致，缺失则标提示并待核。
3. 方证匹配：检查图谱中该方的主治记录是否含证型关键词，匹配标一致，否则标待核。

图谱未收录的药物或方剂会明确标待核，绝不编造归经或组成。

### 用法示例
```
python scripts/verify_graph.py "补中益气汤" --syndrome=脾虚气陷
python scripts/verify_graph.py --herbs=人参,黄芪,升麻
```

## 三、说症状直接出判断的完整链路

`scripts/retrieve.py` 把前面所有能力串成一条流水线，一次运行即出结果。
1. 红旗检查：命中急症信号立即停辨，建议就医或急诊。
2. 五格坐标映射：用内置症状词典把症状映射到位置、性质、力量、物质、病因五个维度，给出候选证型与置信度。
3. 深读分册检索：在 00 至 19 册已深读典籍中检索依据。
4. 848 本语料检索：语料就位时，用倒排索引检索原文片段。
5. 图谱交叉验证（已自动接入）：对候选证型的代表方，调用 `verify_graph.py` 做组成、归经与方证关联复核，结果作为独立段落输出。代表方由证型关键词经 `SYNDROME_FORMULA` 映射确定，组成按三层来源补齐，全部输出为中文，不阻断主流程。

最终输出固定模板：一句话结论、五格坐标、候选证型、能自己做的事、需要医生做的事、图谱交叉验证、深读与语料检索片段。涉及内服方剂剂量、针刺、有毒药材的部分，一律标注须执业中医师面诊后开具，不提供可自行抓药的完整处方。

## 四、安全与版权边界（重申）

- 红旗清单命中的急症，立即停止辨证。
- 方剂只列药味，不给可自行抓药的剂量，标注须医师核定。
- 848 本语料为公有领域古籍文本，引用只取原文短句，白话解释全部原创重写。
- DragonTCM 完整图谱为 CC-BY-NC-4.0 非商业许可，其衍生结论仅作教学与非商业研究，引用须注明来源；种子子集为公有领域常识精选，归经待核项已标注。
- 查不到的依据写待核，不编造篇名、条文号、方剂组成或药物归经。
